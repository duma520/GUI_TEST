# GUI_TEST —— 智能检测系统测试套件（tkinter 图形界面）

> **一句话**：智能检测系统测试套件：把加速后端（CPU / CUDA）、图像算法（原始差分 / 高斯模糊）、帧处理器（单线程 / 多线程）三大模块的 18 个用例做成界面，点一下逐项跑完并显示状态与耗时。改完底层算法先跑它，确认没把别的路径跑坏。

## 2. 零基础入门（5 分钟跑起来）

### 第 1 步：装 Python

1. 打开 <https://www.python.org/downloads/windows/> 下载 Python 3.8 以上版本（3.10 / 3.11 都行）。
2. 安装时**务必勾选** `Add Python to PATH`（加进环境变量），否则后面命令行会提示「不是内部或外部命令」。
3. 装完打开「命令提示符」（按 Win+R，输入 `cmd` 回车），输入：

```bat
python --version
```

能打印出 `Python 3.x.x` 就说明装好了。

### 第 2 步：装依赖

这个程序用到 4 个第三方库（源码里真实 import 的）：

```bat
pip install numpy opencv-python psutil
```

| 库 | 用途 |
|---|---|
| `numpy` | 构造测试用的图像矩阵（`np.zeros`、`np.random`） |
| `opencv-python` | 图像差分、灰度转换、高斯模糊（`cv2.absdiff`、`cv2.GaussianBlur`） |
| `psutil` | 资源占用测试里读 CPU / 内存百分比 |
| `tkinter` / `unittest` | Python 自带，不用装 |

> 如果只是想跑界面看看长什么样，不装这些库会启动失败 —— 源码顶部就是 `import numpy as np` / `import cv2`，缺一个直接报 `ModuleNotFoundError`。

### 第 3 步：启动

两种方式，任选其一：

**方式 A（双击）**：目录里有 `1.bat`，双击它。它会依次运行三个版本的文件：

```bat
cls
python "gui_test - 1.0.0.py"
python "gui_test - 1.0.1.py"
python "gui_test - 1.0.2.py"
```

> 注意：这是**串行**跑三个窗口，关掉第一个才会弹第二个。只想跑最新版，用方式 B。

**方式 B（命令行，推荐）**：

```bat
cd /d 你的项目目录\GUI_TEST
python gui_test.py
```

窗口弹出来后，点底部**「运行全部测试」**，等状态列逐项变色即可。

## 3. 界面逐项说明

### 3.1 左侧：测试用例树（Treeview）

三列结构：

| 列 | 含义 | 取值范围 |
|---|---|---|
| 测试组件/用例 | 用例名称，按组件分组 | 加速后端 / 算法 / 帧处理器 / 性能 / 集成 / 异常 六组 |
| 状态 | 本次运行结果 | 通过 / 失败 / 跳过 / 运行中 / 未执行 |
| 耗时(ms) | 该用例耗时，毫秒 | 整数 |

列宽分别为 300 / 100 / 100 像素，可拖动分隔线调整。

### 3.2 右侧：日志区（Text + Scrollbar）

带垂直滚动条的多行文本框，**只读**（`state=tk.DISABLED`，程序内部临时解锁再写）。记录每条用例的开始、断言结果、异常堆栈。

### 3.3 底部按钮

| 按钮 | 作用 | 什么时候用 |
|---|---|---|
| 运行全部测试 | 依次执行 18 个用例 | 改完代码做整体回归 |
| 运行选中测试 | 只跑树里选中的那几项 | 只改了一个模块，省时间 |
| 清除日志 | 清空右侧文本框 | 日志太长、想重新看一轮 |
| 导出结果 | 把日志写成文件 | 留档、贴给别人看、对比两次结果 |

## 4. 18 个测试用例详解

以下用例名与 `test_methods` 字典里的键**逐字一致**，界面上看到的就是这些中文名。

### 4.1 加速后端（6 项）

| 用例 | 验证什么 |
|---|---|
| CPU初始化测试 | `CPUBackend.initialize()` 能成功置位 |
| CPU帧处理测试 | `CPUBackend.process_frames()` 对两帧做 `cv2.absdiff` + 阈值二值化，输出形状正确 |
| CPU性能测试 | 连续处理多帧的耗时在合理区间 |
| CUDA初始化测试 | `CUDABackend` 在**没有 CUDA 的机器上**能优雅回退到 CPU，而不是崩掉（用 `unittest.mock.patch` 模拟 `cv2.cuda`） |
| CUDA帧处理测试 | 模拟 CUDA 可用时，帧处理输出与 CPU 路径一致 |
| CUDA性能测试 | CUDA 路径（哪怕是 mock）的耗时统计不报错 |

### 4.2 算法（3 项）

| 用例 | 验证什么 |
|---|---|
| 原始算法测试 | 差分算法输出的非零像素位置与预期一致 |
| 高斯模糊测试 | `cv2.GaussianBlur` 预处理后的差分结果比原始更平滑（噪声更少） |
| 算法切换测试 | `AlgorithmManager` 切换算法后，下次处理用的是新算法 |

### 4.3 帧处理器（2 项）

| 用例 | 验证什么 |
|---|---|
| 单线程模式测试 | `FrameProcessor` 单线程路径结果正确 |
| 多线程模式测试 | 多线程路径结果与单线程**完全一致**（不多不少不漏帧） |

### 4.4 性能（3 项）

| 用例 | 验证什么 |
|---|---|
| 低分辨率性能测试 | 小图（如 640×480）下的帧率 / 耗时 |
| 高分辨率性能测试 | 大图（如 1920×1080）下的帧率 / 耗时，用于看是否掉到不可用 |
| 资源占用测试 | 用 `psutil` 读 CPU% 与内存 MB，确认没有越跑越高（泄漏） |

### 4.5 集成（2 项）

| 用例 | 验证什么 |
|---|---|
| CPU+原始算法集成测试 | 后端与算法的组合链路端到端跑通 |
| CUDA+高斯模糊集成测试 | 同上，换成 CUDA + 高斯组合（CUDA 不可用则走回退） |

### 4.6 异常（2 项）

| 用例 | 验证什么 |
|---|---|
| 无效输入测试 | 传空帧 / None / 尺寸不匹配时**抛异常而不是静默返回错值** |
| 硬件异常测试 | 模拟 `cv2.cuda` 抛错时，整体流程能降级继续 |

## 6. 工作原理

```text
gui_test.py 启动
    |
    +-- tk.Tk() 建主窗口 (1200x800)
    |       +-- 左 ttk.Treeview  测试用例树
    |       +-- 右 tk.Text       日志（只读）
    |       +-- 底 ttk.Frame     四个按钮
    |
    +-- test_methods 字典：18 个中文名 -> 对应方法
    |
    +-- 点「运行全部测试」
            |
            +-- 逐项取出方法
            +-- 执行 period 计时 (time.time())
            +-- 捕获 AssertionError / 其他异常
            +-- 回写 Treeview 的 status / time 列
            +-- 追加日志到 Text
```

### 关键技术点

1. **界面线程不能被测试阻塞**：耗时的性能测试会卡住 tkinter 的事件循环（窗口变白、无法拖动）。源码用 `threading` + `queue` 把测试放到后台线程、结果通过队列回主线程刷新 —— 改代码时**不要**去掉这层，否则高分辨率测试一点就假死。
2. **CUDA 测试全部走 mock**：源码用 `from unittest.mock import patch, MagicMock` 给 `cv2.cuda` 打桩，所以在没有 NVIDIA 显卡的机器上也能跑这些用例，通过不代表你机器有 CUDA。
3. **耗时统计范围**：只包住被测方法本身，不含界面刷新时间，所以和真实帧率不是一回事，横向比较同一用例的两次结果才有意义。

## 7. 排错手册

| 现象 | 原因 | 解决 |
|---|---|---|
| 双击 `1.bat` 黑窗一闪就没了 | 缺依赖，Python 报错后立即退出 | 改用 `cmd` 进去手动跑 `python gui_test.py`，就能看到真实报错 |
| `'python' 不是内部或外部命令` | 安装时没勾 PATH | 重装 Python 并勾 `Add Python to PATH`，或用完整路径 `C:\Python310\python.exe gui_test.py` |
| `ModuleNotFoundError: No module named 'cv2'` | 没装 opencv | `pip install opencv-python` |
| `ModuleNotFoundError: No module named 'numpy'` / `'psutil'` | 同上 | `pip install numpy psutil` |
| 界面中文变成方块或乱码 | 控制台/系统编码问题 | 命令行先执行 `chcp 65001` 切 UTF-8 再跑 |
| 点「运行全部测试」后窗口卡死不动 | 某条性能测试没走后台线程，或分辨率过大 | 等它跑完（可能几十秒）；或先只选一条用例试 |
| CUDA 相关用例全部标「跳过」 | 源码里对 CUDA 有 `skipUnless` 之类的判断，本机无卡 | 正常现象，不是缺陷 |
| 杀毒软件报毒 / 拦截 | 打包成 exe 后常见误报 | 加白名单；或直接跑 `.py` 不打包 |

## 8. 常见问题 FAQ

**Q1：这程序和「实时检测系统」是什么关系？**
A：它不负责检测，只负责**测试检测系统的组件**。源码里 `AccelerationBackend` / `AlgorithmManager` / `FrameProcessor` 是「模拟需要测试的核心组件」（源码注释原文），也就是说这些类是为了测试而复制/简化出来的替身，不是生产代码本体。

**Q2：为什么一个目录里有 4 个 py 文件？**
A：是历代版本快照。1.0.0 → 1.0.1 → 1.0.2 逐步加用例；`gui_test.py` 是 1.0.2 的副本（MD5 相同）作为固定入口名。

**Q3：跑全部测试要多久？**
A：正常在十几秒到几十秒之间，取决于「高分辨率性能测试」那张图多大、以及机器性能。日志里每条都有耗时，可以自己加总。

**Q4：没有 NVIDIA 显卡能跑吗？**
A：能。CUDA 用例全用 `unittest.mock` 打桩，测的是「代码在 CUDA 缺失/异常时的逻辑」，不是真显卡性能。

**Q5：能测真实的检测精度（比如漏检率）吗？**
A：不能。18 个用例都是**代码级断言**（形状对不对、结果一致不一致、耗时在不在区间），没有真实数据集与标注，不产出准确率 / 召回率这类指标。

**Q6：导出的结果文件在哪？是什么格式？**
A：点「导出结果」后由 `export_results` 方法写盘，格式是**纯文本日志**（不是 JSON / HTML）。具体文件名看源码里 `export_results` 的实现，界面不提示路径。

**Q7：可以只跑一条用例做调试吗？**
A：可以，用「运行选中测试」。也可以把对应方法名写进自己的脚本单独跑。

**Q8：改了被测组件的代码，这个套件能自动跟着测吗？**
A：不能。被测组件是**内联复制**在这个文件里的类（`AccelerationBackend` 等），你在别的项目改了生产代码，这里的替身不会变。要测真代码，需把这些类换成 `import` 真实模块。

**Q9：为什么窗口是 1200×800 固定尺寸？**
A：`self.root.geometry("1200x800")` 写死的。小屏幕（1366×768 笔记本）会超屏，可以手动拖小，或改源码里的这个数值。

**Q10：能打包成单个 exe 发给别人吗？**
A：能，用 PyInstaller：`pyinstaller -F -w gui_test.py`。`-w` 表示不带黑窗。注意 opencv 打包体积会到 100MB 以上。

## 10. 已知限制与安全说明

- **无真实数据集**：所有测试用随机 / 全零图像构造，不覆盖真实场景光照、噪声、遮挡。
- **被测组件是替身**：见 FAQ Q8，不能替代生产代码的集成测试。
- **CUDA 全 mock**：不验证真实 GPU 计算正确性与显存占用。
- **固定窗口尺寸**：1200×800 写死，低分辨率屏幕体验差。
- **无自动化 CI**：只能人工点按钮，不支持 `--headless` 或返回码给流水线判成败。
- **不联网、不写系统目录**：只读本机 CPU/内存数据（psutil），不上传任何信息。
